# /bsl-check — проверка BSL-кода

> **OpenCode:** `{SKILL_DIR}` в командах — каталог текущего навыка. Подставь абсолютный путь к каталогу
> навыка, если среда не делает это автоматически. Команды запускай из корня проекта.

Запускает [BSL Language Server](https://github.com/1c-syntax/bsl-language-server) в режиме анализа
по каталогу выгрузки и печатает короткую сводку: файл, строка, уровень, код диагностики, текст.
Находит синтаксические ошибки, функции без `Возврат`, неиспользуемые переменные, нарушения стандартов
1С — **до** загрузки в базу, без цикла «загрузка → ошибка платформы → правка».

## Команда

```bash
node "{SKILL_DIR}/scripts/bsl-check.mjs" -Path "<каталог или файл>" [-Severity Warning] [-Limit 60]
```

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `-Path` | — | Каталог выгрузки (лучше узкий: расширение `src/cfe/Имя` или объект `src/cf/Documents/Задача`) или файл `.bsl` |
| `-Severity` | `Warning` | Максимальный уровень в выводе: `Error` — только ошибки, `Warning` — ошибки и предупреждения, `Information`/`Hint` — всё |
| `-Limit` | `60` | Сколько строк замечаний показать |
| `-Status` | | Показать, где установлен BSL LS и его версию |
| `-Install` | | Скачать или обновить BSL LS (около 170 МБ) в `~/.config/opencode/tools/bsl-language-server` |

Код выхода: `0` — ошибок нет, `1` — есть ошибки (уровень `Error`), `2` — проверка не выполнена
(BSL LS не установлен, нет каталога).

## Как использовать

1. После правки модулей проверь **только изменённый** каталог — расширение или объект. Вся типовая
   конфигурация (ERP, УТ) проверяется несколько минут и даёт тысячи замечаний.
2. Исправь все замечания уровня «ошибка». Предупреждения — по смыслу: в чужом (типовом) коде их не трогай.
3. Повтори проверку; когда ошибок нет — переходи к загрузке (`db-load-xml` / `db-load-git`).

Если BSL LS не установлен, скрипт напишет, как его поставить:
`node "{SKILL_DIR}/scripts/bsl-check.mjs" -Install`. Свой экземпляр BSL LS можно указать
переменной окружения `BSL_LS_PATH` (путь к `bsl-language-server.exe`, к каталогу или к `*-exec.jar` — тогда
нужна Java 17+). Настройки диагностик берутся из `.bsl-language-server.json` в корне проекта, если он есть.

## BSL LS как инструменты OpenCode

Проект также подключает BSL LS как MCP-сервер `1c-bsl` (если BSL LS установлен). Его инструменты удобны
для точечной работы с одним модулем:

| Инструмент | Для чего |
|------------|----------|
| `analyze_file` | Диагностика одного файла `.bsl` |
| `document_symbols` | Области, методы, переменные модуля |
| `definition`, `find_references`, `call_hierarchy` | Переход к определению, ссылки, граф вызовов (по позиции: файл, строка, символ — с нуля) |
| `type_info`, `global_member_info`, `global_member_search` | Справка по типам и методам платформы (синтакс-помощник; нужна установленная платформа 1С) |

После каждой правки `.bsl`/`.os` (инструменты `edit`, `write`, `patch`) плагин OpenCode `bsl-autocheck` сам проверяет
изменённые файлы и дописывает ошибки и предупреждения к результату правки — исправляй их сразу. Плагин смотрит только
изменённые файлы; перед загрузкой в базу всё равно проверяй каталог целиком этим навыком (`-Path` расширения или
изменённых объектов).

Для поиска объектов и методов по имени во всей выгрузке удобнее инструменты сервера `1c-search`
(`find_object`, `find_method`, `find_usages`).
