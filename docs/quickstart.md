# Быстрый старт: goose (с окном) + навыки 1С

Пошаговая инструкция для тех, кто раньше не работал с AI-агентами. Всё делается в обычном окне
программы **goose Desktop** на Windows — командную строку открывать не нужно.

**Что получится:** вы выбираете папку своего 1С-проекта и пишете задачу обычными словами:
«добавь в справочник Номенклатура реквизит Вес», «собери обработку», «открой в браузере список
заказов». goose сам выполняет её с помощью навыков 1С.

**Из чего это состоит:**
- **goose Desktop** — программа-агент с окном чата. Она выполняет действия на вашем компьютере:
  запускает команды, правит файлы.
- **Модель (LLM)** — «мозг» агента, работает в облаке через интернет. Нужен аккаунт у поставщика
  моделей (обычно платный).
- **Навыки 1С** — 81 готовая инструкция со скриптами для работы с выгрузками 1С, базами
  и веб-клиентом.

---

## Шаг 1. Установите вспомогательные программы

| Программа | Зачем | Где взять |
|-----------|-------|-----------|
| **Git for Windows** | Обязательна. goose через неё выполняет команды навыков (Git Bash) | https://git-scm.com/download/win — при установке везде жмите «Next» |
| **Node.js** (LTS) | Для работы через браузер и защиты типовых конфигураций | https://nodejs.org — большая зелёная кнопка «LTS» |
| **1С:Предприятие 8.3** | Для сборки обработок и работы с базами. Если вы только правите XML-выгрузки — можно без неё | у вас уже есть |

## Шаг 2. Установите goose Desktop

1. Скачайте архив:
   https://github.com/aaif-goose/goose/releases/download/stable/Goose-win32-x64.zip
2. Распакуйте его в удобную папку, например `C:\Programs\goose`.
3. Запустите **Goose.exe**. Для удобства закрепите значок на панели задач: правой кнопкой →
   «Закрепить на панели задач».

## Шаг 3. Подключите модель и включите русский язык

1. При первом запуске откроется экран **«Добро пожаловать в goose»** с выбором поставщика модели.
   - Самый простой вариант — **OpenRouter**: войдите или зарегистрируйтесь в браузере, пополните
     баланс, и goose настроится сам.
   - Если у вас уже есть ключ (Anthropic, OpenAI, Google и т.п.), выберите этого поставщика
     и вставьте ключ.
2. **Какую модель выбрать.** Навыки 1С большие, им нужна сильная модель, которая хорошо работает
   с инструментами: старшие модели Claude, GPT, Gemini. Маленькие, бесплатные и локальные модели
   справляются плохо.
3. Язык интерфейса: **Settings → App → Language → Русский**. После переключения:
   **Настройки → Приложение → Язык**.

## Шаг 4. Установите навыки 1С

1. Откройте https://github.com/mika-com/1C_MCP_GOOSE, нажмите зелёную кнопку **Code** →
   **Download ZIP**.
2. Распакуйте архив в любую папку, например в «Загрузки».
3. Откройте распакованную папку и **дважды щёлкните `install-windows.cmd`**.
4. В окне должны появиться зелёные строки `[1/6]` … `[6/6]` и надпись «Готово». Нажмите любую клавишу.
   Первый раз установка идёт дольше: скачивается BSL Language Server (около 170 МБ).

Что сделал установщик:
- скопировал навыки в `C:\Users\<ваше имя>\.agents\plugins\1c` — оттуда их берёт goose;
- настроил goose на выполнение команд через Git Bash (без этого навыки на Windows не работают);
- увеличил время на одну команду до часа — обновление базы и выгрузка бывают долгими;
- добавил в goose расширения **1c-ask** (форма уточняющих вопросов), **1c-search** (поиск по выгрузке)
  и **1c-bsl** (проверка кода) — после перезапуска goose они видны в меню слева **«Расширения»**;
- скачал **BSL Language Server** в `C:\Users\<ваше имя>\.agents\tools` — goose проверяет им код модулей
  до загрузки в базу (навык `bsl-check`);
- скопировал **рецепты** этапов работы в `C:\Users\<ваше имя>\.agents\recipes` (см. шаг 7).

Если строки красные или жёлтые, прочитайте их. Обычно не хватает Git или Node.js: установите их
(шаг 1) и запустите `install-windows.cmd` ещё раз. Скачанную папку после установки можно удалить.

5. **Полностью закройте goose** и запустите снова. Если значок goose остался в области уведомлений
   у часов — правой кнопкой по нему → выход. Иначе goose не увидит новые настройки.
6. Проверка: в меню слева откройте **«Навыки»**. Там должны быть навыки 1С: `epf-init`,
   `meta-info`, `form-edit`, `bsl-check` и другие (всего 82). В разделе **«Рецепты»** — четыре рецепта «1С: …».

## Шаг 5. Откройте папку проекта

goose работает в одной папке — **корневой папке вашего 1С-проекта**, где лежит XML-выгрузка
конфигурации или обработок (например, `C:\Projects\MyApp` с подпапкой `src`).

1. Нажмите **«Новый чат»**.
2. Внизу окна нажмите на название текущей папки → **«Выбрать каталог…»** → выберите папку проекта.

Название папки внизу окна должно смениться на ваш проект. Для следующих чатов её можно выбрать
из **«Недавних каталогов»**.

**Рекомендуется:** скопируйте файл `.goosehints` из `C:\Users\<ваше имя>\.agents\plugins\1c\goose\`
в корень папки проекта. В нём короткие правила для goose: как работать с 1С-проектом и чего не делать.

## Шаг 6. Выберите режим подтверждений

**Настройки → Чат → Режим:**

| Режим | Что делает |
|-------|-----------|
| **Умный** | Спрашивает разрешение только на рискованные действия — **рекомендуется** |
| **Вручную** | Спрашивает перед каждым действием — для осторожных, но подтверждать придётся часто |
| **Автономный** | Ничего не спрашивает — только если проект под Git и всё можно откатить |
| Только чат | Без действий — навыки работать не будут |

## Шаг 7. Работайте

Пишите задачи в поле чата обычными словами:

- «Покажи структуру справочника Номенклатура»
- «Добавь в справочник Номенклатура реквизит Вес, тип Число(15,3)»
- «Создай внешнюю обработку ЗагрузкаЦен с формой и кнопкой Загрузить»
- «Проверь все роли на ошибки»
- «Сделай расширение и перехвати в нём процедуру ПередЗаписью документа РеализацияТоваров»

goose сам выберет навык, выполнит действия и расскажет о результате. Под сообщениями видно,
какие команды он запускал. Навык можно вызвать и явно, через косую черту: `/epf-init ЗагрузкаЦен`.

**Рецепты — работа по этапам.** Для доработки удобнее не один длинный чат, а четыре коротких. В меню
слева откройте **«Рецепты»** и запустите нужный — goose спросит параметры и начнёт новый чат с
инструкциями именно для этого этапа:

| Рецепт | Что делает | Что указать |
|--------|-----------|-------------|
| **1С: анализ и план доработки** | Изучает выгрузку и составляет план. Ничего не меняет | Задачу своими словами |
| **1С: доработка по плану** | Вносит изменения навыками и проверяет их (`*-validate`, `bsl-check`). В базу не загружает | План из первого этапа |
| **1С: загрузка в базу** | Проверка кода → ваше подтверждение → загрузка, обновление базы, безопасный режим расширения | Базу и расширение |
| **1С: проверка в браузере** | Проверяет доработку в веб-клиенте и описывает ошибки | Что проверить |

В конце каждого этапа goose предложит следующий рецепт. Так модель не путается в длинной истории,
а чат стоит дешевле.

**Поиск и проверка кода.** goose сам ищет объекты и методы инструментами `find_object` («найди регистр
с историей задач»), `find_method` («покажи код процедуры ПередЗаписью»), `find_usages` («кто вызывает
ЗаполнитьИсторию») — без чтения огромных XML. Перед загрузкой в базу он проверяет модули навыком
`bsl-check`. Попросить можно и явно: «проверь расширение через bsl-check».

Каждая новая задача — лучше в **новом чате**: так goose не путается в старом контексте и тратит
меньше денег. Прошлые чаты лежат в **«Истории сеансов»**.

**Уточняющие вопросы формой.** Плагин добавляет goose инструмент `ask_user`: когда в задаче не хватает
данных, goose показывает в чате форму — вопросы с вариантами ответа (выпадающий список), полем для
своего варианта и флажками «да/нет». Заполните и нажмите **«Отправить»**. На ответ даётся 5 минут:
потом форма закрывается, и goose продолжает без ответа (по правилам должен остановиться и спросить
в чате). Для формы нужен Node.js (шаг 1).

> Установщик добавляет в goose три расширения — их видно в меню слева **«Расширения»** с переключателями:
> **1c-ask** (форма вопросов), **1c-search** (поиск по выгрузке), **1c-bsl** (проверка кода BSL LS).
> Все три должны быть включены. Они появляются только в **новых** чатах, открытых после установки
> и перезапуска goose. Проверка: в новом чате напишите «Есть ли у тебя инструмент ask_user? Задай мне
> через него один вопрос».

**Если goose не задаёт уточняющих вопросов**, а сразу делает «по умолчанию»:
- скопируйте в проект свежий `.goosehints` (шаг 5): в нём есть правило «уточняй, прежде чем делать»;
- добавьте к задаче: «**сначала задай уточняющие вопросы через ask_user и составь план, ничего
  не меняй до моего ответа**» — это работает надёжнее всего;
- для постоянного правила включите **Top Of Mind** (шаг 10) с этим текстом в файле правил: goose
  будет видеть его в каждом сообщении;
- не используйте режим «Автономный»: в нём goose ничего не согласует.

> **Совет:** держите проект под Git. Если goose сделает что-то не то, изменения легко откатить.

## Шаг 8. Подключите базу 1С (если нужна)

Для сборки обработок, загрузки конфигурации в базу и обновления нужны платформа и информационная
база. Напишите goose:

> «Зарегистрируй базу: файловая, путь C:\Bases\MyApp_Dev, платформа C:\Program Files\1cv8\8.3.24.1691\bin,
> выгрузка конфигурации в папке src\cf»

goose создаст в папке проекта файл `.v8-project.json` с этими настройками
([пример](../.v8-project.example.json), [подробно](v8-project-guide.md)). После этого можно просить:

- «Загрузи изменения из src\cf в базу и обнови конфигурацию»
- «Выгрузи конфигурацию базы в XML»
- «Собери обработку ЗагрузкаЦен в epf»

Если базы ещё нет: «Создай новую файловую базу в C:\Bases\Test».

> В `.v8-project.json` могут лежать пароли. Если проект в Git, добавьте строку `.v8-project.json`
> в файл `.gitignore`.

## Шаг 9. Работа через браузер (необязательно)

goose умеет открывать базу в веб-клиенте 1С и работать в нём: нажимать кнопки, заполнять формы,
проверять отчёты, записывать видеоинструкции.

1. Нужна **опубликованная база**:
   - если база уже опубликована на веб-сервере — сообщите goose адрес: «у базы dev адрес
     http://server/dev»;
   - если нет — «Опубликуй базу dev через Apache». goose скачает Apache в папку `tools` проекта
     и опубликует базу. Нужна платформа с компонентом веб-расширения.
2. В первый раз goose сам установит браузер для автоматизации — это займёт пару минут.
3. Просите: «Открой в браузере список заказов клиентов и создай заказ для контрагента Альфа»,
   «Проверь, что отчёт Продажи за май формируется без ошибок».

## Шаг 10. Полезные расширения (необязательно)

Расширения добавляют goose новые возможности. Включаются так: меню слева **«Расширения»** →
переключатель напротив нужного. Встроенные расширения ставить не нужно — они уже есть, их нужно
только включить.

**Рекомендуемый набор: Developer + Todo + Memory**, плюс Computer Controller, если работаете
с документами Word/Excel.

| Расширение | Что даёт для 1С | Как включить |
|------------|-----------------|--------------|
| **Developer** | Основа: команды и правка файлов. Без него навыки 1С не работают | уже включено — **не выключайте** |
| **Todo** | goose составляет план из шагов и отмечает выполненные. Помогает в длинных задачах: «сделай расширение, заимствуй объекты, перехвати методы, загрузи в базу, проверь в браузере» | переключатель |
| **Memory** | Запоминает факты между чатами: «тестовая база — dev», «собираем на 8.3.24», «префикс наших объектов — мк_». Скажите: «запомни, что…» | переключатель |
| **Chat Recall** | Поиск по прошлым чатам: «как мы в прошлый раз чинили загрузку цен?» | переключатель |
| **Computer Controller** | Читает и создаёт документы **Word, Excel, PDF**: ТЗ заказчика, таблица для загрузочной обработки, описание API | переключатель |
| **Top Of Mind** | Правила, которые goose помнит в каждом сообщении: «никогда не загружай в базу prod», «не меняй общие модули БСП» | переключатель + файл с правилами (см. ниже) |

**Правила для Top Of Mind.** Создайте текстовый файл, например `C:\Users\<ваше имя>\goose-rules.txt`,
и запишите в него правила по одному в строке. Затем укажите goose путь к файлу: Пуск → введите
«переменные среды» → **«Изменение переменных среды текущего пользователя»** → «Создать…»:
имя `GOOSE_MOIM_MESSAGE_FILE`, значение — путь к файлу. Перезапустите goose. Правила действуют
во всех проектах.

**По ситуации** (внешние расширения, ставятся из каталога https://goose-docs.ai/extensions/
кнопкой установки):

- **GitHub** — если проект на GitHub: задачи, пул-реквесты и ревью прямо из чата. Нужен токен GitHub.
- **PDF Reader** — большие или защищённые PDF, например сохранённые статьи ИТС.
- **Tavily** — веб-поиск по ИТС, Инфостарту и форумам. В goose уже есть встроенный поиск, поэтому
  это нужно, только если его не хватает. Нужен ключ Tavily.

**Не включайте:**
- **Playwright, Puppeteer, Chrome DevTools, Selenium** — браузером уже управляет навык `web-test`,
  и он знает веб-клиент 1С. Второй инструмент для браузера только запутает goose.
- **Postgres** и другие прямые подключения к СУБД — работать с базой 1С в обход платформы опасно,
  а таблицы 1С называются вида `_Reference123`.
- **Всё подряд** — каждое включённое расширение добавляет описания своих инструментов в каждый
  запрос к модели: это дороже, и модель чаще ошибается. Включайте только то, чем пользуетесь.

## Разбор: что делал goose и на что ушли токены

**Во время работы.** Включите **Настройки → Приложение → Отслеживание стоимости** — goose будет
показывать цену запросов. Под сообщениями goose в чате видно каждое действие: разверните его, чтобы
увидеть команду и ответ.

**После работы — отчёт по сеансу.** Нужен Python 3 (https://www.python.org, при установке отметьте
«Add python.exe to PATH»).

1. Сохраните сеанс: **«История сеансов»** → наведите мышь на нужный сеанс → кнопка скачивания →
   **JSON**. Файл попадёт в «Загрузки».
2. Откройте папку `C:\Users\<ваше имя>\.agents\plugins\1c\scripts`, щёлкните в адресной строке
   проводника, введите `cmd` и нажмите Enter. В открывшемся окне:

   ```
   python analyze_session.py "%USERPROFILE%\Downloads\<файл сеанса>.json" -o "%USERPROFILE%\Desktop\отчёт.md"
   ```

   В PowerShell (строка начинается с `PS`) пишите `$env:USERPROFILE` вместо `%USERPROFILE%`.
   Скрипт понимает оба варианта, но старая версия скрипта понимает только тот, что подходит для вашей
   командной строки.

   Без экспорта, прямо из истории goose: `python analyze_session.py --list` покажет последние сеансы,
   `python analyze_session.py --db` разберёт последний, `--session <ID>` — конкретный.

Что покажет отчёт:
- сколько было запросов к модели, токенов и сколько это стоило; какие шаги самые дорогие;
- какие навыки goose загрузил, а какие скрипты навыков запускал «по памяти», не читая инструкцию;
- **хождение по кругу**: одинаковые команды и серии ошибок подряд;
- правил ли goose XML выгрузки вручную вместо навыков;
- самые большие ответы команд: они раздувают историю и дорожают в каждом следующем запросе;
- рекомендации, что поменять.

**Разбор сильной моделью.** Добавьте `--transcript "%USERPROFILE%\Desktop\расшифровка.md"` — получится
сжатая расшифровка сеанса: запросы, команды, ответы. Её можно показать более сильной модели
и спросить: «где агент потратил лишнее и что поменять в подсказках или навыках?». Перед тем как
кому-то пересылать расшифровку, просмотрите её: в ней могут быть пути, имена баз и пароли из команд.

## Обновление

- **Навыки 1С:** снова скачайте ZIP (шаг 4) и запустите `install-windows.cmd`, затем перезапустите goose.
- **goose:** **Настройки → Приложение → Обновления**.

## Если что-то не работает

| Проблема | Что сделать |
|----------|-------------|
| В «Навыках» нет навыков 1С | Запустите `install-windows.cmd` ещё раз и полностью перезапустите goose (шаг 4, пункт 5) |
| Команды падают с ошибками вроде `'RUN' is not recognized`, непонятные ошибки про `<<` или `&` | goose не видит настройку Git Bash. Полностью закройте goose (и в области уведомлений) и запустите снова. Не помогло — перезагрузите компьютер |
| Установщик пишет «Git Bash не найден» | Установите Git for Windows (шаг 1) и запустите установщик ещё раз |
| Команда обрывается примерно через 5 минут | То же, что выше: перезапустите goose или компьютер, чтобы применилась настройка времени |
| goose правит XML вручную вместо навыка | Скопируйте `.goosehints` в проект (шаг 5) или напишите прямо: «используй навык meta-edit» |
| «Редактирование отклонено: объект на поддержке» | Это защита типовой конфигурации. Попросите сделать доработку в расширении. Если правка точно нужна — «разреши редактирование объекта через support-edit» |
| Кракозябры вместо русских букв в ответе команды | Попросите goose сохранять вывод в файл и читать его (это правило есть в `.goosehints`) |
| Нет формы вопросов (`ask_user`) или в «Расширениях» нет 1c-ask, 1c-search, 1c-bsl | Запустите `install-windows.cmd` ещё раз: в строке `[4/6]` должно быть «Форма вопросов: ask_user OK» и «Расширения 1С (1c-ask, 1c-search, 1c-bsl) записаны в …config.yaml». Если Node.js не найден — установите его (шаг 1). Затем полностью закройте goose (и в области уведомлений), запустите снова, проверьте, что расширения включены, и откройте **новый** чат. Не помогло — «Переустановка goose начисто» ниже |
| «BSL Language Server не установлен» | Запустите `install-windows.cmd` ещё раз (шаг 4): в строке `[5/6]` должно быть «установлен». Если скачивание блокирует сеть — скачайте вручную `bsl-language-server_win.zip` со страницы https://github.com/1c-syntax/bsl-language-server/releases и распакуйте в `C:\Users\<ваше имя>\.agents\tools\bsl-language-server` |
| Компьютеру не хватает памяти, когда открыто много чатов | Каждый чат запускает свой BSL LS (Java, 300–500 МБ). Закрывайте лишние чаты или отключите сервер: переменная среды `BSL_LS_MCP` = `off` (проверка `bsl-check` продолжит работать) |
| Первый поиск по выгрузке долгий | goose строит индекс выгрузки: для ERP — до минуты, дальше секунды. Индекс хранится во временной папке Windows |
| `Cannot find package 'playwright'` | Напишите goose: «установи зависимости web-test» |
| goose не видит файлы проекта | Проверьте папку внизу окна (шаг 5) |

## Переустановка goose начисто

Если goose ведёт себя странно (нет навыков или формы вопросов, ошибки при запуске, путаница после
нескольких установок), переустановите его с чистыми настройками. Старые данные не удаляйте,
а **переименуйте** — так можно вернуть историю чатов или откатиться.

**1. Сохраните нужное.** Если нужны прошлые чаты — экспортируйте важные («История сеансов» → кнопка
скачивания → JSON). Найдите ключ API модели: после переустановки его нужно ввести заново.

**2. Полностью закройте goose.** Правой кнопкой по значку goose у часов → выход. Затем в Диспетчере
задач (Ctrl+Shift+Esc) убедитесь, что нет процессов `Goose.exe` и `goosed.exe`; если есть — «Снять задачу».

**3. Удалите программу.** Удалите папку, куда распаковывали goose (например `C:\Programs\goose`).
Проверьте «Загрузки» и «Рабочий стол»: нет ли там других распакованных копий — запускать нужно одну.

**4. Переименуйте папки настроек.** В адресной строке проводника введите `%APPDATA%` и нажмите Enter:
- папку `Block\goose` переименуйте в `goose.old`: настройки, ключи, история чатов, логи, промпты;
- папку `Goose` (если есть) переименуйте в `Goose.old`: данные окна программы.

Папку `C:\Users\<ваше имя>\.agents` (навыки 1С) можно не трогать — её обновит установщик на шаге 8.

**5. Проверьте переменные среды.** Пуск → «переменные среды» → **«Изменение переменных среды текущего
пользователя»**. Среди переменных, начинающихся с `GOOSE_`, должны остаться только:
- `GOOSE_SHELL` — путь к `bash.exe`; проверьте, что этот файл существует;
- `GOOSE_DEFAULT_EXTENSION_TIMEOUT` — `3600`;
- `GOOSE_MOIM_MESSAGE_FILE` — если включали Top Of Mind.

Другие `GOOSE_*` (например `GOOSE_PROVIDER`, `GOOSE_MODEL`, `GOOSE_MODE`), если вы их добавляли,
удалите: они перекрывают настройки из окна goose и часто вызывают путаницу.

**6. Установите goose заново** — как в «Шаге 2» выше: свежий архив, распаковать в простую папку
(`C:\Programs\goose`), запустить `Goose.exe`.

**7. Настройте модель и язык** — как в «Шаге 3» выше. Если пользовались своим поставщиком (например DeepSeek через
«пользовательского провайдера»), добавьте его заново: эти настройки остались в `goose.old`.

**8. Переустановите навыки 1С** — как в «Шаге 4» выше: свежий ZIP репозитория → `install-windows.cmd`. Все строки
должны быть зелёными, в `[4/6]` — «Форма вопросов: ask_user OK» и «Расширения 1С … записаны». Затем снова
полностью закройте и запустите goose: в «Расширениях» появятся включённые 1c-ask, 1c-search, 1c-bsl.

**9. Проверьте.** «Навыки» в меню слева — есть навыки 1С. В **новом** чате выберите папку проекта
и напишите: «Есть ли у тебя инструмент ask_user? Задай мне через него один вопрос» — должна появиться форма.

**Вернуть старую историю чатов** (необязательно): при закрытом goose скопируйте файл
`%APPDATA%\goose.old\data\sessions\sessions.db` в `%APPDATA%\Block\goose\data\sessions\` с заменой.
Если всё работает, папки `goose.old` и `Goose.old` можно удалить.

## Дополнительно: goose в командной строке (CLI)

Если удобнее терминал, то же самое делается в **Git Bash**:

```bash
curl -fsSL https://github.com/aaif-goose/goose/releases/download/stable/download_cli.sh | bash
goose configure                                           # подключить модель
goose plugin install https://github.com/mika-com/1C_MCP_GOOSE
node ~/.agents/plugins/1c/mcp/register-extensions.mjs     # расширения 1c-ask, 1c-search, 1c-bsl
cd /c/Projects/MyApp && goose session                     # работать в папке проекта
```

Настройки из шага 4 (Git Bash и время на команду) нужны и для CLI: запустите `install-windows.cmd`
или задайте переменные вручную:
`setx GOOSE_SHELL "C:\Program Files\Git\bin\bash.exe"` и `setx GOOSE_DEFAULT_EXTENSION_TIMEOUT 3600`.

`install-windows.cmd` и `goose plugin install` кладут навыки в одну и ту же папку
`.agents\plugins\1c`, поэтому нужен только один из них. Если папка уже есть, `goose plugin install`
откажется ставить повторно: обновляйте тем же способом, которым ставили.

На **Linux/macOS** Git Bash не нужен. Установите Python 3 и зависимости
(`pip install -r ~/.agents/plugins/1c/requirements.txt`): без PowerShell goose запускает
Python-версии скриптов.
