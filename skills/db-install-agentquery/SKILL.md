# /db-install-agentquery — Расширение чтения данных AgentQuery

> **OpenCode:** `{SKILL_DIR}` в командах — каталог текущего навыка. Подставь абсолютный путь к каталогу навыка, если среда не делает это автоматически. Команды запускай из корня проекта. Если `powershell.exe` недоступен (Linux/macOS), запусти одноимённый `.py`-скрипт через `python` (или `python3`) с теми же параметрами.

> **Пароль (OpenCode).** Не передавай `-Password`, `/P`, `--password`. Достаточно `-Database <id>`: загрузку выполняет `db-load-xml`, он берёт соединение и пароль из `.v8-project.json`. Значение пароля в команду и в ответ не попадает.

Ставит готовое расширение `AgentQuery` (исходники в `{SKILL_DIR}/extension`) в выбранную базу и обновляет конфигурацию базы. Это обычный вызов `db-load-xml -Extension AgentQuery`, не самодельный `1cv8` и не обработка `.epf`.

Расширение — дополнение (`AddOn`): свой HTTP-сервис `AgentQuery`, корневой URL `agentquery`, шаблон `/query`. `GET` отвечает, что сервис жив, `POST` выполняет только `ВЫБРАТЬ`. Роль `AQ_ОсновнаяРоль` в основных ролях расширения даёт право `Use` на эти методы и не выдаёт права на данные: запрос идёт от пользователя записи базы, с его RLS.

Безопасный режим расширения снимать не нужно: модуль не ходит в файлы и COM, только выполняет запрос.

## Параметры подключения

Прочитай `.v8-project.json` и передай **только** `-Database <id>` (id, не пароль). Скрипт сам найдёт `configSrc` этой базы и подставит uuid языка, чтобы заимствованный язык совпал с конфигурацией. Если `configSrc` пуст — передай `-ConfigPath` на каталог выгрузки с `Configuration.xml` и `Languages/`.

Без выгрузки базы uuid языка остаётся нулевым, и платформа загрузку, скорее всего, отвергнет. Так и скажи, не собирай расширение заново другим навыком.

## Команда

```powershell
powershell.exe -NoProfile -File "{SKILL_DIR}/scripts/db-install-agentquery.ps1" -Database "dev"
```

```powershell
python "{SKILL_DIR}/scripts/db-install-agentquery.py" -Database "dev" -ConfigPath "src/cf"
```

| Параметр | Обязательный | Описание |
|----------|:------------:|----------|
| `-Database <id>` | да* | id базы из `.v8-project.json` |
| `-ConfigPath <путь>` | нет | Выгрузка конфигурации, если у базы нет `configSrc` |
| `-InfoBasePath` / `-InfoBaseServer` + `-InfoBaseRef` | * | Вместо `-Database`, если базы нет в реестре |
| `-V8Path <путь>` | нет | Каталог `bin` или `1cv8.exe` / `ibcmd.exe` |
| `-NoUpdate` | нет | Не обновлять конфигурацию базы после загрузки |
| `-PrepareOnly` | нет | Только подготовить каталог XML, платформу не запускать |
| `-OutputDir <путь>` | нет | Куда положить подготовленные исходники |

> `*` — нужен `-Database` либо параметры соединения. `-Password` нет.

## После выполнения

1. Опубликуй базу навыком `web-publish`, если `webUrl` ещё пуст. Публикация этого репозитория уже включает HTTP-сервисы расширений (`publishExtensionsByDefault`) и стандартный OData.
2. Проверь готовность инструментом `query_db` с `action: "status"` и тем же `database`. Ответ «готова» значит, что GET сервиса вернул `service=AgentQuery`.
3. Иначе читай текст: нет адреса, адрес не отвечает, HTTP 404 (не загружено или не опубликовано), HTTP 401/403 (пользователь или пароль в `.v8-project.json`), HTML вместо JSON (в `queryUrl` попал веб-клиент, а не `/hs/agentquery/query`).

На живой платформе загрузка этого каталога не прогонялась: нет базы 1С в среде сборки. Если платформа отвергнет формат новее 2.17, в выводе будет пометка — пришли её текст, не переписывай модуль вручную.
