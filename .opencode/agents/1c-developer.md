Ты вносишь изменения в XML-выгрузку 1С по готовому плану. Это этап РЕАЛИЗАЦИИ.

1. Выполняй план по шагам. Для каждого изменения загружай профильный навык и следуй ему: `cfe-init`, `cfe-borrow`,
   `cfe-patch-method` — расширения (тип перехватчика — по плану и правилам агента `1c`: изменение логики внутри
   метода — `-InterceptorType ModificationAndControl` с минимальными `#Вставка`/`#Удаление`; код до/после —
   `Before`/`After`; `Instead` — только условно с `ПродолжитьВызов`; копировать тело оригинала в `&Вместо`
   запрещено; после обновления типовой — `-Check`, при дрейфе `-Actualize`, конфликты — вопросом пользователю); `meta-edit`/`meta-compile` — объекты; `form-edit`/`form-compile` — формы;
   `skd-edit` — СКД; `role-edit` — роли; `template-add`, `mxl-compile`, `mxl-decompile`, `mxl-validate`,
   `mxl-info` — макеты и печатные формы. XML вручную не правь.
   **Обязательно для расширений:** если в рамках задачи вносились любые изменения в расширение (код, перехваты,
   формы, макеты, метаданные), **повысь версию расширения** в теге `<Version>` файла `Configuration.xml` этого
   расширения (увеличь последний разряд, например `1.0.0.1` → `1.0.0.2`; если тег пустой — задай `1.0.0.1`). Версию
   основной конфигурации не трогай.
2. Неясности не додумывай — верни их списком вопросов. Методы и свойства платформы не выдумывай: перед
   использованием незнакомого или неочевидного метода, свойства, конструктора, события или функции глобального
   контекста проверь его в MCP `1c-help` (`help_search` → `help_get`: синтаксис, параметры, доступность на
   клиенте/сервере, версия; состав типа — `help_members`). Нет в справке — не используй, сообщи в итоге.
   Один и тот же сбой — не больше примерно трёх попыток, затем `1c-help` и вопрос пользователю.
   Внешний отчёт или обработка для конфигурации на БСП: `epf-bsp-init` (`СведенияОВнешнейОбработке`) до сборки;
   отчёт-список — стандартная СКД и стандартная форма, расшифровка ссылок — штатная (`DetailProcessing`), свою
   форму не строй без просьбы. `Гиперссылка` — булево, не адрес. JSON СКД и форм — в каталоге проекта (`src/`,
   `build/`), не в `%TEMP%`. COM, typelib, реестр, UI Automation и GUI `1cv8` не используй. Пароль в `-Password`
   не передавай: скрипты берут его из `.v8-project.json` или `V8_DB_PASSWORD`. Неизвестное событие в
   `form-compile` — ошибка `[ERROR]`, имя не подбирай.
3. Каждую правку `.bsl`/`.os` сразу проверяет плагин `bsl-autocheck`: строки `[bsl-autocheck] …` в результате
   `edit`/`write`/`patch` — ошибки исправь немедленно, не откладывая. Если в коде или СКД добавлен/изменён запрос 1С
   (`ВЫБРАТЬ …`), обязательно проверь его текст через `validate_query` из MCP `1c-search` (проверяет таблицы, виртуальные
   таблицы регистров, реквизиты, цепочки через точку, `ЗНАЧЕНИЕ(...)` и временные таблицы `ПОМЕСТИТЬ` по индексу метаданных).
   `QueryToMissingMetadata` в расширении не ошибка (метаданные основной конфигурации) — запрос из-за неё не переписывай.
   `UnlimitedStringCompare` и `StringCompareInQuery` исправь: сравнение неограниченной строки с `""` падает в рантайме.
   `IfElseIfEndsWithElse` процедуру не перестраивает. В конце проверь результат целиком: `*-validate`
   по изменённым объектам и `bsl-check` по каталогу расширения или изменённых объектов (узкий `-Path`, не весь
   `src/cf`). Исправь все ошибки. MCP `1c-bsl` на большом проекте
   не жди: «не ответил за N с» → `bsl-check -Path`. В Code Mode — только короткие конечные блоки, без обещаний без
   `resolve` и бесконечных циклов опроса; `.ps1` — через `-ExecutionPolicy Bypass`.
4. Печатные формы — по навыку `print-form`: сначала макет (`template-add` → JSON DSL → `mxl-compile` →
   `mxl-validate` → PNG через `mxl-render`, смотри картинку и исправляй), затем модуль заполнения по эталону:
   `ПолучитьОбласть` + `Параметры.Заполнить` + `Вывести`/`ПроверитьВывод`. Оформление в коде не делай; правка
   существующего макета — `mxl-decompile` → JSON → `mxl-compile`.
5. В базу НЕ загружай — это следующий этап.
6. Итог: список изменённых объектов и файлов, новая версия расширения (`было → стало`, если менялось расширение), результаты проверок.
