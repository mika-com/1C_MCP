# Быстрый старт: goose + навыки 1С

Пошаговая инструкция для тех, кто раньше не работал с AI-агентами. Описан Windows — на нём работает
большинство разработчиков 1С. Для Linux/macOS — короткий раздел в конце.

**Что получится:** в папке своего 1С-проекта вы пишете задачу обычными словами («добавь в справочник
Номенклатура реквизит Вес», «собери обработку», «открой в браузере список заказов»), а goose сам
выполняет её с помощью навыков 1С.

**Как это устроено:**
- **goose** — программа-агент. Она выполняет команды на вашем компьютере и правит файлы.
- **Модель (LLM)** — «мозг» агента, работает в облаке через интернет. Нужен аккаунт и ключ доступа (платный).
- **Плагин `1c`** — 81 навык. Это готовые инструкции и скрипты для работы с выгрузками 1С, базами
  и веб-клиентом.

---

## Шаг 1. Установите программы

| Программа | Зачем | Где взять |
|-----------|-------|-----------|
| **Git for Windows** | Даёт терминал **Git Bash**: в нём работает goose и выполняются команды навыков | https://git-scm.com/download/win — при установке везде можно жать «Next» |
| **Node.js** (LTS) | Нужен для тестирования через браузер и для защиты типовых конфигураций | https://nodejs.org — кнопка «LTS» |
| **1С:Предприятие 8.3** | Нужна для сборки обработок и работы с базами. Если вы только правите XML-выгрузки — можно без неё | у вас уже есть |
| Python 3 (необязательно) | Нужен только если PowerShell недоступен (Linux/macOS) | https://www.python.org |

После установки откройте **Git Bash** (Пуск → «Git Bash») и проверьте:

```bash
git --version
node --version
```

Обе команды должны напечатать номер версии.

> Дальше все команды выполняются в **Git Bash**. Чтобы вставить текст в его окно, используйте
> правую кнопку мыши → Paste или `Shift+Insert`.

## Шаг 2. Установите goose

В Git Bash:

```bash
curl -fsSL https://github.com/aaif-goose/goose/releases/download/stable/download_cli.sh | bash
```

Если в конце появится предупреждение, что goose нет в `PATH`, выполните:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

Проверка: `goose --version` печатает номер версии.

## Шаг 3. Подключите модель

goose сам ничего «не понимает» — ему нужна модель. При первом запуске (или командой `goose configure`)
откроется мастер настройки:

```bash
goose configure
```

Самый простой путь — **OpenRouter Login**: откроется браузер, вы входите в аккаунт OpenRouter,
пополняете баланс, и goose настраивается сам. Можно выбрать и **Manual Configuration**, если у вас уже
есть ключ (Anthropic, OpenAI и т.п.).

**Какую модель выбрать.** Навыки большие, им нужна сильная модель, которая хорошо работает
с инструментами: старшие модели Claude, GPT, Gemini. Маленькие и бесплатные модели с навыками 1С
справляются плохо.

> На Windows при ручной настройке, если мастер спросит про keyring (хранилище ключей), ответьте «нет».

## Шаг 4. Настройте goose под навыки (один раз)

В Git Bash выполните две команды:

```bash
setx GOOSE_SHELL "C:\Program Files\Git\bin\bash.exe"
setx GOOSE_DEFAULT_EXTENSION_TIMEOUT 3600
```

- **Первая** — чтобы goose выполнял команды через Git Bash. Без неё на Windows навыки работать не будут:
  по умолчанию goose использует `cmd`, а команды навыков написаны для bash.
- **Вторая** — чтобы долгие операции (обновление базы, выгрузка, сборка) не обрывались через 5 минут.

Если Git установлен не в `C:\Program Files\Git`, поправьте путь. **Закройте Git Bash и откройте заново** —
иначе настройки не подхватятся.

## Шаг 5. Установите плагин 1С

```bash
goose plugin install https://github.com/mika-com/1C_MCP_GOOSE
```

Должно появиться `✓ Installed open-plugins plugin '1c'` и список навыков `1c:...`. Проверка:

```bash
goose skills list
```

## Шаг 6. Подготовьте папку проекта

goose работает в той папке, из которой его запустили. Это должна быть **корневая папка вашего 1С-проекта** —
та, где лежит XML-выгрузка конфигурации или обработок (например, `C:\Projects\MyApp` с подпапкой `src`).

```bash
cd /c/Projects/MyApp
```

> В Git Bash диск `C:` пишется как `/c/`, а вместо `\` используется `/`.

Скопируйте в проект подсказки для goose — короткие правила, как работать с 1С-проектом:

```bash
cp ~/.agents/plugins/1c/goose/.goosehints .
```

## Шаг 7. Работайте

Запустите goose в папке проекта:

```bash
goose session
```

Пишите задачи обычными словами. Примеры:

- «Покажи структуру справочника Номенклатура»
- «Добавь в справочник Номенклатура реквизит Вес, тип Число(15,3)»
- «Создай внешнюю обработку ЗагрузкаЦен с формой и кнопкой Загрузить»
- «Проверь все роли на ошибки»
- «Сделай расширение и перехвати в нём процедуру ПередЗаписью документа РеализацияТоваров»

goose сам выберет навык, покажет, что собирается сделать, выполнит команды и расскажет о результате.
Можно вызвать навык явно: `/1c:epf-init ЗагрузкаЦен`.

**Подтверждения.** По умолчанию goose может спрашивать разрешение перед командами. Режим меняется прямо
в сессии:

| Команда | Что делает |
|---------|-----------|
| `/mode smart_approve` | спрашивает только про рискованные действия — **рекомендуется** |
| `/mode approve` | спрашивает перед каждым действием — для осторожных |
| `/mode auto` | ничего не спрашивает — только для проекта под Git, где всё можно откатить |

Выход из сессии — `exit` или `Ctrl+C`.

> **Совет:** держите проект под Git (`git init`, затем коммиты). Если goose сделает что-то не то,
> изменения легко откатить.

## Шаг 8. Подключите базу 1С (если нужна)

Для сборки обработок, загрузки конфигурации в базу и обновления нужны платформа и информационная база.
Попросите goose:

> «Зарегистрируй базу: файловая, путь C:\Bases\MyApp_Dev, платформа C:\Program Files\1cv8\8.3.24.1691\bin,
> выгрузка конфигурации в папке src\cf»

goose создаст в проекте файл `.v8-project.json` с этими настройками
([пример](../.v8-project.example.json), [подробно](v8-project-guide.md)). После этого можно просить:

- «Загрузи изменения из src\cf в базу и обнови конфигурацию»
- «Выгрузи конфигурацию базы в XML»
- «Собери обработку ЗагрузкаЦен в epf»

Если базы ещё нет: «Создай новую файловую базу в C:\Bases\Test».

> Пароли из `.v8-project.json` не должны попасть в Git: добавьте строку `.v8-project.json`
> в файл `.gitignore` проекта.

## Шаг 9. Работа через браузер (необязательно)

goose умеет открывать базу в веб-клиенте 1С и работать в нём: нажимать кнопки, заполнять формы,
проверять отчёты, записывать видеоинструкции.

1. Нужна **опубликованная база**:
   - если база уже опубликована на веб-сервере — скажите goose её адрес: «у базы dev адрес
     http://server/dev»;
   - если нет — «Опубликуй базу dev через Apache». goose скачает Apache в папку `tools` проекта
     и опубликует базу. Нужна платформа с компонентом веб-расширения.
2. В первый раз goose сам поставит Playwright и браузер Chromium — это займёт пару минут.
3. Просите: «Открой в браузере список заказов клиентов и создай заказ для контрагента Альфа»,
   «Проверь, что отчёт Продажи за май формируется без ошибок».

## Обновление

```bash
goose plugin update 1c   # навыки 1С
goose update             # сам goose
```

## Если что-то не работает

| Проблема | Что сделать |
|----------|-------------|
| `goose: command not found` | Шаг 2 — добавить goose в `PATH`, перезапустить Git Bash |
| Команды падают с ошибками вроде `'RUN' is not recognized`, `<<` или `&` | Не настроен `GOOSE_SHELL` (шаг 4). Проверка: `echo $GOOSE_SHELL`. После `setx` нужен перезапуск терминала |
| goose не видит навыки 1С | `goose skills list` должен показывать `1c:...`. Если пусто — повторите шаг 5 |
| Команда обрывается на 5-й минуте | Не применился `GOOSE_DEFAULT_EXTENSION_TIMEOUT` (шаг 4) |
| goose правит XML вручную вместо навыка | Скопируйте `.goosehints` (шаг 6) или скажите прямо: «используй навык 1c:meta-edit» |
| «Редактирование отклонено: объект на поддержке» | Это защита типовой конфигурации. Попросите сделать доработку в расширении. Если правка точно нужна — «разреши редактирование объекта через support-edit» |
| Кракозябры вместо русских букв в выводе | Попросите goose сохранять вывод в файл и читать его (подсказка уже есть в `.goosehints`) |
| `Cannot find package 'playwright'` | Скажите goose: «установи зависимости web-test» — команда есть в навыке |
| Ошибки ключа / keyring при настройке модели | Шаг 3: при ручной настройке не сохранять в keyring |

## Linux и macOS

- Терминал — обычный, Git Bash и `GOOSE_SHELL` не нужны.
- Установка goose и плагина — те же команды (шаги 2, 3, 5).
- Вместо `setx` добавьте в `~/.bashrc` (или `~/.zshrc`) строку
  `export GOOSE_DEFAULT_EXTENSION_TIMEOUT=3600`.
- Поставьте Python 3 и зависимости:
  `pip install -r ~/.agents/plugins/1c/requirements.txt`. Без PowerShell goose будет запускать
  Python-версии скриптов.
- Навыки работы с XML работают полностью. Работа с базами — через `ibcmd` или платформу 1С для Linux.
  Веб-публикация через портативный Apache рассчитана на Windows.
