# Проект 1С:Предприятие 8.3

Этот проект работает с агентом `1c` для OpenCode (навыки cc-1c-skills, MCP `1c-search`, `1c-bsl`, `1c-help`, `vrunner`).

- Корень XML-выгрузки: `src/` <!-- поправьте под свой проект -->
- Базы, платформа и веб-публикация описаны в `.v8-project.json` (пример — `.v8-project.example.json`).
- Доработки типовой конфигурации делаются только в расширениях.
- «Где реализовано X» — сначала `semantic_search` из `1c-search` (по смыслу; без LM Studio — по ключевым словам),
  для анализа связей объекта (обязательные реквизиты `FillChecking`, движения, подписки, расширения, типы, декодирование ссылок `e1cib/data/...?ref=`) — `object_refs`. Если в `.v8-project.json` несколько баз, передавай `database` или `path_filter` во все вызовы `1c-search`.
- Любой новый или изменённый запрос 1С проверяется статически через `validate_query` из `1c-search` (включая антипаттерны производительности ИТС). Строки живой базы читает `query_db` (id базы, только `ВЫБРАТЬ`, лимит и таймаут обязательны). Ошибки
  выполнения в базе диагностируются через `event_log` (чтение `.lgd`/`.lgp` с привязкой стека к `.bsl`).
- После каждой правки `.bsl` плагин `bsl-autocheck` показывает ошибки BSL LS — их исправляют сразу; перед загрузкой
  в базу каталог проверяется навыком `bsl-check`. `QueryToMissingMetadata` и `CommonModuleInvalidType` в расширении — не ошибка.
  Строки `[bsl-autocheck]` нет — плагин не активен (часто старая установка): версия 1C-Agent видна в ответах MCP `1c-search` (`index_status`).
- Загрузку расширения в базу делает агент `1c-deployer`, проверку в браузере — `1c-tester`. Сразу после первой
  загрузки расширения снимают безопасный режим, и только потом открывают веб-клиент.
- Проверка — веб-публикация и `web-test`. Плагин `shell-guard` не даёт запустить COM любой версии, интерактивный `1cv8` и загрузку конфигурации в базу мимо навыков `db-*`.
- Внешний отчёт/обработка на БСП — сразу `epf-bsp-init`; отчёт-список — стандартная СКД и штатная расшифровка.
- Пароль в командную строку не передавать: навыки берут его из `.v8-project.json` или `V8_DB_PASSWORD`.
- Длинная задача — по этапам (`/1c-analyze` → `/1c-implement` → `/1c-webtest`), с планом и согласием.
